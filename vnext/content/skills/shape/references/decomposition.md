# Decomposition

Decomposition changes native work structure, so it must improve independent verification rather than merely shorten a description.

## Promote a Child When

- One criterion has its own observable completion evidence.
- It can be implemented or reviewed independently without making the parent misleading.
- Its blockers or sequencing differ materially from the parent.
- A separate native identity improves ownership or collaboration.

Keep a criterion on the parent when separation would create a coordination shell, duplicate context, or turn one coherent change into bookkeeping. When a child is justified, create or resolve the native record, write its complete work contract, then establish the native parent relationship and verify both sides through readback.

Dependencies are not hierarchy. Record a blocking edge only when one work item genuinely cannot complete before another; use parent/child only for decomposition.
