The calibration Codex lacked: this gate is accident-proofing, not tamper-proofing

A repo owner who wants to cheat can edit the gate's own source — no receipt format survives that. Findings are scored by one question: can this happen innocently in the normal workflow? The shaping-only merge could (that's the defect). Hand-forged receipts cannot. This reframe becomes a Rabbit Hole line in the doc.

The one real design change: the receipt becomes a cache of verify, not a credential

Codex's critical (2.1) is right — a criteria-only digest stays valid after a regression or revert. Its fix ("expire on any change") is a re-verification treadmill. Ours: the receipt records the criteria digest and the commit it verified; at release preflight, receipt-commit ≠ HEAD re-runs the executable criteria instead of trusting stale evidence. Cost lands only on arc terminals at stable cuts — the rarest ceremony. Once the receipt is the real lock, provenance demotes to a coarse filter and three adversarial findings collapse.

1.2high"Executable criteria" have no executable representationaccept · design

Codex

Plan

Decide the contract shape in the doc: executable V-entries declare their command and expected result; prose stays H-series (human review). Exact syntax lands at T5 against the capability-receipt precedent — rule of latitude, not a schema spec in shaping.

Requiring all boxes resurrects status-pressure. Textual fix only: say this out loud, and resolve the --require-executable open question as provenance-only.

2 · Gate soundness vs the current implementation

2.1criticalA criteria-only receipt survives regression and revertaccept · modified mechanics

Codex

After a legitimate receipt commits, a later revert outside the change folder leaves digest and provenance valid — stable opens on code that no longer passes verification.

Plan

Receipt = cache of verify: records criteria digest + verified commit. Preflight with receipt-commit ≠ HEAD re-runs the executable criteria — fresh evidence at the rare moment it matters. Codex's expire-on-any-change rejected as a treadmill. Decision 13 rewritten; weaker than our own capability-receipt precedent was the tell.

2.2highSingle-content changeNode can't feed both consumersaccept · cheap

Codex

New-layout metadata lives in change.json, structural validity in shape.md; the one-file node feeding deriveChangeGraph and evaluateChangeDocAtPath serves neither.

Plan

Correct implementation guidance, not a design change: T1 gains a sentence — replace the single-content node with parsed metadata plus per-layout contract evaluation, migrating both graph and preflight consumers.

2.3highThe predecessor-immutability premise is factually falseaccept · factual correction

Codex

The replay freezes only lineage and release-after; predecessor mutation is deliberately legal (TestReleaseLineagePreflightAllowsCommittedPredecessorEvolution) to allow node insertion.

Plan

The doc claimed otherwise — our error, caught against code. Corrected: only arc and terminal freeze; previous stays evolvable, preserving insertion between committed nodes. Decision 3 + Immutability section rewritten.

2.4highDeletion history: too narrow for new layout, too strict for conversionaccept · design

Codex

The retention guard only recognizes deleted /change.md paths — deleting change.json is invisible, while converting an old lineage-bearing unit is permanently blocked.

Plan

One decision covers 2.4 + 4.1: the retention guard extends to change.json, and sanctioned conversion is defined — an atomic same-commit replace where frozen values carry over verbatim (the replay already validates continuity). Folds into T1 + Immutability.

2.5mediumV2 overstates the prerelease bypassaccept · cheap

3 · Adversarial

3.1highMixed-commit execution launderingcollapses with 2.1

Codex

A shaping commit touching a task file plus any unrelated outside path satisfies execution.

Plan

With the verify-cache receipt, provenance alone can't open the gate. Remaining half addressed cheaply: the terminal-satisfaction path uses checkbox-flip detection (diff parse at preflight, one folder, rare); non-terminals stay path-level. No general commit-purpose analysis.

3.2highNon-semantic task-file touches count as executioncollapses with 3.1

Codex

Whitespace, title edits, or adding an unchecked box all satisfy the path-level rule.

Plan

Same resolution: checkbox-flip detection at the terminal gate; receipt is the lock everywhere else. Accepted residual for non-terminal display states, where nothing releases on it.

3.3highReceipt gaming — weakened criteria, hand-authored receiptsreject · threat model

Codex

Criteria can be weakened to a trivially passing command and re-verified; without tool-provenance format the receipt can be hand-authored.

Plan

Deliberate evasion is out of scope: the owner also owns the gate's source and any signer. Weakened criteria are a shape.md diff — exactly what human review of an arc terminal exists to catch. Recorded as the accident-not-tamper Rabbit Hole so this isn't re-litigated.

3.4highOld-layout fallback preserves the shaping/execution ambiguitysubsumed by 1.1 + 2.1

Codex

A legacy shaping edit plus an unrelated outside path is indistinguishable from delivery; the receipt can't mitigate without a legacy digest.

Plan

The legacy digest (1.1) plus verify-cache receipts (2.1) give the old-layout terminal the same real lock. One clarifying sentence in Compatibility; no separate mechanism.

Plan
