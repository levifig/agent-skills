✓ No gate involvement. A standalone Change never blocks a release — the next loaf release of any kind simply includes whatever landed. Half-done is safe by construction: unstarted tasks are absent features, never broken ones.
Diagram 2b

Change lifecycle — bound to a target release

Same lifecycle per change — declaring target_release opts it into the strong gate, and the cohort (everything sharing the target) must finish before that version cuts stable.

release cohort · target_release: 2.0.0
member Aexecuted ✓ · receipt fresh ✓
member Bexecuted ✓ · receipt fresh ✓
member Cshaped only — blocks 2.0.0

◌ prerelease door — always open

loaf release --bump prerelease flows in every arc state — alphas keep shipping mid-arc.

⛔ stable door — locked mid-arc

release blocked: change "…" targets 2.0.0 but is not executed
shaping-only merges can no longer open it (the proven 2026-07-25 attack).
… member C's tasks land (checkbox flips + paths outside docs/changes/) → loaf change verify runs the declared criteria → receipt commits (criteria digest + verified commit) …

◌ prerelease door — still open

Nothing changes for alphas; they never depended on the arc.

✓ stable door — opens on evidence

materialized ∧ valid ∧ executed ∧ receipt current at HEAD.
Receipt stale (a later commit beyond the receipt's own)? Preflight re-runs verify — fresh evidence, not stale trust. The cohort is complete — derived, nothing written.

a cohort exists the moment any change declares target_release: X — cutting X stable is blocked until the cohort finishes; every other release is unaffected · target_release is mutable: retargeting to a later version is the visible, reviewable exit; retargets are surfaced from history, never blocked · nothing freezes, nothing is written at completion
